# 画面与纸带：视觉规范

> 整套只有三种材质：**冷白纸、碳带黑、印泥红**。刻意避开工程里已有的全部暖色系（旧纸米、暗金、火光、暖纸桌面）。
> 竖屏 1080×1920，纸从上往下吐出，纵向运动。

---

## 二、版面常量

| 常量 | 值 | 说明 |
|---|---|---|
| `PAPER_W` | 880 | 纸宽，左右各留 100 台面 |
| `TITLE_Y` | 300 | 标题区起点 |
| `FIRST_Y` | 610 / 838 | 第一行数据（按场景调） |
| `LINE_H` | 88 | 行高 |
| `KEEP_BOTTOM` | 1560 | **纸底硬上限**，超过就压字幕 |
| 字幕顶边 | 1683 | 字幕盒子顶边，倒推纸底 ≤1600 |
| 安全区 | 上 170 / 下 230 | 平台 UI 遮挡 |

**纸底 > 1600 会盖住字幕**，用户反馈过「有一小部分会盖住画板，不雅观」。所有场景的纸高、行距都要按这条反推。

## 三、纸（`Paper`）

- 齿孔：`PERF_HOLE` 每 26px 一个小圆，圆心穿透到台面色，左右各一条 16px 宽。
- 横纹：`PAPER_LINES` 每 52px 一道压痕。
- 顶部柔光：`radial-gradient(ellipse 80% 40% at 50% 0%, rgba(255,255,255,0.62), transparent 62%)` —— 纸刚从机器里出来那层反光。
- 底部撕口：`tornBottom` 给一条 122° 锯齿。
- 投影：`0 34px 80px rgba(0,0,0,0.62), 0 6px 18px rgba(0,0,0,0.4)`。

**三条硬规律**

1. **纸必须跟着内容长**：
   ```ts
   const paperH = Math.max(1180, FIRST_Y + smoothIdx * LINE_H + 250);
   ```
   固定高度 → 后半屏一大片死白，「纸的长度 = 花掉的钱」的隐喻就废了。
2. **打印时长必须短于行间隔**：`printLen = gap * 0.85`。固定 9 帧而加速后 gap 只有 6 帧 → 两行打架。
3. **纸要从「出纸口」出来**，不能凭空飘着：顶部 `top:-44 / h:142` 深色机身 + `y:78` 出纸缝 + 右上角暗红指示灯，纸底加台面倒影渐变。

## 四、六种镜头动作

| 动作 | 用途 | 要点 |
|---|---|---|
| **打印** | 逐行出账 | `clipPath: inset(-18px {1-p}% -18px 0)` 从左往右揭示，行尾跟墨块光标 |
| **滚纸** | 段落推进 | 纵向（区别于长卷版横向漫游） |
| **盖章** | 合计、关键数字 | `Stamp` 双线红章，缩放砸下，配 `stamp` 音效 |
| **撕纸** | 平均数 vs 中位数 | **上下撕**，下半截坠落出画（竖屏不能左右撕） |
| **划线** | 否定一个数字 | 红笔，见下方角度规则 |
| **翻面** | 讲算不出来的成本 | 背光，纸纹透出来 |

### 红笔删除线的角度规则（返工过三轮）

| 版 | 第一道 | 第二道 | 反馈 |
|---|---|---|---|
| v12 | 10.4° | 10.1°（完全平行、间距恒定） | **太歪** |
| v13-a | 2.7° | 4.1°（不平行） | 第二道太靠下 |
| **定稿** | **2.7°（y144→114）** | **4.1°（y182→138）** | 通过 |

- **角度要么 0–4°、要么 25°+，绝不要 8–15°**。中间区间人眼判为「画歪了」而不是风格。
- **手写感来自不平行 + 长度不等 + 起点错开**，不是加波浪。v12 加了波浪但完全平行，还是像机器画的。
- **路径坐标对着字形实际范围算，不是对着 div 盒子**。132px 字号、line-height 1.2 时盒子 158，字形只有约 95 —— 按盒子定位会让下面的线掉到字外。
- 揭示用 `clipPath: inset(...)` 从左到右，两条线错开 2 秒（分别绑 `cf(4)` / `cf(5)`）。

## 五、组件签名（`kit.tsx`）

```tsx
<Paper width height style? perf? tornBottom?>{children}</Paper>

<ReceiptRow n age name amount progress head? top width fs? dim? />
// 单行：序号 / 年龄 / 说明 / 点线 / 金额

<StageHead top width />                                  // 四列表头
<StageRow idx age name monthly total months progress head? top width highlight? />
// highlight 0..1 → 该行描红 + 左侧红竖条，跟着口播走

<Caption text p bottom? />                               // 底部结论句，默认 bottom 244
<Stamp ... />                                            // 双线红章
```

**`COL` 列宽**（占 `width` 的比例，改字号必须同步改）：

```ts
const COL = {idx: 0.055, age: 0.19, name: 0.245, m: 0.21, t: 0.30};
```

## 六、字号：手机可读性（放大清单）

用户反馈「这些数字在手机上看都很小」。各放大约 20–25%，说明文字同步跟一档避免比例失衡。

| 位置 | 项 | 原 | 现 |
|---|---|---:|---:|
| 总账表 `StageRow` | 这一段每月 | 30 | **36** |
| | 这一段一共 | 38 | **44** |
| | 表头 `StageHead` | 22 | **24** |
| 阶段特写 | 每月金额 | 76 | **88** |
| | 段总额 | 40 | **48** |
| | 横条右侧数值 | 36/30 | **46/38** |
| | 元/月 · 这段一共 | 26/24 | **30/28** |
| 八段总览 | 每行总金额 | 26 | **34** |
| 地区 | 数值 | 30 | **38** |
| 边际 | 平均金额 | 50 | **56** |
| | 19 年那列 | 38 | **44** |
| 撕纸 | 折合每月 | 46 | **52** |

**放大必须同步改的几何（否则溢出）**

- `COL`：m 列要 ≥158px 才放得下 36px 的 `2,543.84`；t 列要 ≥226px 才放得下 44px 的 `187,812.72`；name 列让出 23px，字号 20 保持，9 字不换行。
- 阶段特写横条最大宽 **470 → 420**：46px 数值右对齐到 660，横条原来到 556 会重叠。
- 地区数值列 `left 676/width 144` → `left 648/width 176`：38px 下 8 字符「3,227.94」要 152px。

**物理上限**：边际成本段的「每月」列已经到极限，再放大会撞到相邻列。要更大只能砍列或换版面。

## 七、分区与场景切换

```tsx
{f < SEG.turn.from ? <SceneOpen /> : null}                    // ✅ 用下一段的 from
{f >= SEG.turn.from && f < SEG.fetal.from ? <SceneTurn /> : null}
{f >= s.seg.from && f < s.seg.to ? <StageScene ... /> : null}
{f >= SEG.end.from ? <EndScene ... /> : null}                 // 最后一段只判 from
```

**用自己段的 `to` 会整段黑屏**（ep60 上造成 413–1056 帧全黑，只有抽帧才看得到）。

换场统一在 `seg.from + 2` 落一记 `whoosh`，画面和声音同时换，观感才像「翻页」而不是「跳变」。

## 八、片尾

- 最后一段必须挂**数据来源注脚**：报告名 + 数据年份 + 口径（例「中国生育成本报告 2026 版 · 2024 年价格」）。
- 结尾一句问句把球踢给观众（「你家养娃，每个月大概花多少？」），配 `ding`。
- 注脚字号小但要**能看清**，别放到字幕安全区里。

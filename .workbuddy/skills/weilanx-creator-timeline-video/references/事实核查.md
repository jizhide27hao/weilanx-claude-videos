# 事实核查

写完文案、做完画面，**导出前必须逐条核一遍**。这不是形式主义：这一期 58 条硬信息里查出 12 条有问题，而且全都不是笔误，是「听起来很对、其实站不住」的那种，光看文案根本看不出来。

核查的产物是 `docs/<期>-核查.json`，再由 `scripts/doc.py` 排成给人看的 md。

## 一、核什么：六类硬信息

只核有出处可查的。观点、形容、情绪、时间顺序不在范围内。

| 类型 | 例子 | 雷区 |
|---|---|---|
| 数字 | 6112 万台、450 亿美元、26 亿亏损 | 口径、单位、财年 vs 自然年 |
| 日期 | 2011.8.16、2018.7.9、2025.6.27 | 发布日 vs 上市日 vs 开售日 |
| 引语 | 「这是最后一次重大创业」 | **没找到原话就不能加引号**，不能写「他说」 |
| 名次 / 首次 | 中国第一、全球第二、最年轻 | 中国口径 ≠ 全球口径 |
| 因果 | 「因为缺货所以被骂」 | 因果要有出处，不能靠推理 |
| 绝对说法 | 第一次、唯一、最、全部、从未 | 只要有反例就得改 |

## 二、怎么查

**优先级从高到低**：官方一手（公司大事记 / 投资人关系页 / 年报 / 官方新闻稿）→ 权威机构（IDC、Canalys、Counterpoint、IHS、财富、交易所公告）→ 主流媒体交叉核对（只用来佐证，不单独作为依据）。

几条实操经验：

- **公司史先查官网大事记**。小米的 `mi.com/global/company/` 和 IR 页面有时间线，出生日期、发布会日期、上市日期这种都在。
- **出货量必须写清口径**：IDC 和 Canalys 的中国数字和全球数字能差一个名次。「跌出前五」这种说法在中国口径和全球口径下结论完全相反。
- **股价和市值分盘中 / 收盘**。同一句「1.55 万亿」，盘中高点对应和当日收盘对应是两个数。
- **股价类数字有保鲜期**。写稿当天查到的数，两周后就过期了。所以要么出片当天重新取，要么用「近 7000 亿」「21 港元出头」这种留余量的说法。
- **引语查原话**。找不到就说「当时外界评价」，不要编成「他说」。
- **绝对说法查反例**。「智能机第一次砸到千元以下」——查一下就会发现 2011 年就有千元智能机，这句话直接站不住。
- WebSearch 结果里带日期的更可靠；同一事实至少两个独立来源一致才写进片里。

## 四、查完之后改文案的三条纪律

改文案是有成本的，因为画面全靠 `cf(n)` / `cw(n,'词')` 挂在第几句上。

1. **条数不能变**。改文本可以，增删句子会让后面所有 `cf(n)` 错位。真要增删，就得把所有 `cf` 重排一遍。
2. **改完检查所有 `cw(n,'词')` 里的词还在不在新句子里**。不在了会直接抛「cue n 里没有某词」，渲染时才发现就晚了。跑一次 `grep -o "cw([0-9]*, *'[^']*')"` 对照新文案逐条看。
3. **画面上的硬编码文字必须同步改**。口播改了「掉到第五」，画面印章还写「跌出前五」，观众截图就会挂出来。改完在 `film.tsx` / `art.tsx` / `timeline.ts` 里 grep 一遍旧说法，确认清零。

## 五、核查配置怎么写

`docs/<期>-核查.json`：

```json
{
  "title": "小米 16 年",
  "lede": "一句话说明这期讲什么",
  "tail": 0.9,
  "segs": [[1, 7, "钩子"], [8, 14, "2010 银谷大厦"]],
  "checks": [
    [1, "已改", "2026-10-20 收盘 27.06 港元、总市值 6967 亿。原文 6614 亿是 9 月数据。"],
    [8, "无误", "小米官网大事记：2010-04-06 成立。"],
    [43, "存疑", "两种说法都查得到，片里按 A 说，交付时说明。"]
  ],
  "notes": "可选，markdown 原样追加到文稿末尾（画面文字同步清单、已知取舍都写这里）"
}
```

- `checks` 三列是「第几句 / 结论 / 依据」，结论只有 `无误` / `已改` / `存疑`。
- `segs` 必须连续覆盖全部句子，`doc.py` 会校验，漏一句直接报错（故意的，写漏一句整张表就错位了）。
- 依据要写**具体来源 + 数字**，不要写「查过了没问题」。三个月后回来看，只写「查过了」等于没查。

## 六、交付时必须说的事

- 改了几条、分别是什么（列原话和实际）。
- 哪几条查不到明确出处（`存疑`），需要用户自己拍板。
- 哪些数字有保鲜期，什么时候会过期。
- 如果某个说法改完影响了标题或封面文案，一并说明。

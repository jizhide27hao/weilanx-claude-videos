# 画面与桌面

时间轴长卷的全部画面是**一张 26500 × 1080 的旧纸桌面**，故事节点按年份钉在桌面上，相机沿着桌面横移，边走边讲。没有切镜，只有推拉。

样片：`src/episodes/ep52-xiaomi-history/`（小米 16 年）、`ep20-nvidia-history`（英伟达 33 年）、`ep19-apple-history`、`ep18-ai-history`。

## 一、坐标系：三件事

```
WORLD_W = 26500   WORLD_H = 1080
RULER_Y = 930     时间尺贴在桌面下方
```

**1. 年份 → 横坐标**（`timeline.ts`）

```ts
export const yx = (year: number) => lerp(ANCHORS, year, 0);   // 年份 → x
export const xy = (x: number) => lerp(ANCHORS, x, 1);         // x → 年份
```

`ANCHORS` 是 `[年份, x]` 数组，**非线性**：故事密度高的年份要拉宽。这一期把 2016 危机和 2025.6–2026.8（顶点到腰斩）两段拉得很宽，其余按年份密度分段线性映射。

写新一期时先列时间节点，再决定哪 2 段值得拉宽，然后铺 `ANCHORS`，整个桌面的疏密就定下来了。

**2. 每个故事节点的横坐标**

```ts
const X = {
  found: yx(2010.3),
  mi1: yx(2011.65),
  ipo: yx(2018.55),
  // ...
};
```

一律写 `yx(年份)`，**不要手写数字**。手写的话改 `ANCHORS` 之后所有节点都会错位。

**3. 命运线**（数值曲线，可选但强烈建议）

```ts
export const CAP: [number, number][] = [[2018.52, 4300], [2025.49, 15500], [2026.8, 6967]];
export const capY = (v: number) => 820 - 340 * (Math.log10(v) - Math.log10(CAP_FLOOR));
```

对数刻度，红色折线贯穿全片，随相机推进逐段生长。**它把「数字」变成全片的时间脊椎**：观众不用记住每个市值，只要看这条线怎么起怎么落。曲线要标「示意」。

## 二、相机

```ts
const CAM: CamKey[] = [
  {f: 0, x: X.now - 330, y: 430, z: 1.28},
  {f: cf(5), x: X.now - 180, y: 470, z: 1.05, ease: 'sine', dur: 30},
  {f: cf(8) - 2, x: X.found - 80, y: 470, z: 1.1, ease: 'tail', dur: 30},
];
```

- `f` 一律用 `cf(n)`，**跟着字幕走**。这句说完了相机就到下一个节点，不需要手算秒。
- `ease`：`sine` 用在同一节点内的微调（缓慢漂移），`tail` 用在跨节点的长距离移动（开头快、结尾缓）。`dur` 20–30 帧。
- 同一节点的典型写法是**两个关键帧**：`cf(段首) - 4` 用 `tail` 把镜头摆到位，`cf(段中)` 用 `sine` 再往前推一点，让画面一直在动。
- `z` 控制在 1.05–1.15，超过 1.2 会显得挤，低于 0.9 字看不清。
- **相机 `x` 别照抄上面的 `- 80 / - 100`，要跟这一页元素的横向分布配平。** 上面那个偏移只是「内容围着节点左右各铺 600–700」时的手感值；如果一页的元素其实都在 `x - 700 … x + 600`（ep58 就是这样），再额外往左偏 100，等于把整页推右 130px —— 左边一大条空白、右边直接压出画框。**开渲前把这一页最左、最右的元素代进第三节的公式，两边留白各留 ≥ 80px**；页面特别宽时（> 1400 世界像素）单独把这一段的 `z` 降下来，别为了对齐去挪元素。
- **但也不是「统一改成 `- 30` 就完事」。** ep58 二十来个节点的元素横向分布各不相同（有的全挂 `x - 660`，有的挂 `x + 190`），统一偏移的结果是：一部分页左贴边、一部分页右边空一大片。**每页的偏移要单独量**：取这一页最后一句的静止帧（相机 `camAt` 的关键帧是「移动结束点」，稳定窗口结束于下一个关键帧的 `f - dur`），渲一帧 1920×1080，量出内容包围盒，`cam.x = 包围盒中点`，`z = min(原z, 0.92 × 1920 / 包围盒世界宽度)`。ep58 二十页里偏移从 `- 190` 到 `+ 75` 都有。
- **想「把整页往中间挪」，优先挪内容，而不是把相机往左推。** 相机往左走会把**上一页**挂在 `x - 600` 的东西拉进画框，在左边缘留一条被切掉半截的卡片（ep58 罚单页就这么翻过车：相机左推 290 之后，蚂蚁页的「按融资规模」「两万亿的估值，停在纸上」全被切在左边）。改成把这一页内容整体右移 330，相机原地不动，问题是干净的。
- **桌面纸只有 `WORLD_W` 这么长**，收尾镜头最容易露馅：`cam.x` 不能大于 `WORLD_W - 960 / z`，否则画面右边会露出纸外的一截（ep58 收尾就踩过，最后两个关键帧退到 `X.final - 250 / - 190` 才盖住）。

## 三、一个故事节点的写法

```tsx
const Founding: React.FC<{f: number}> = ({f}) => {
  const x = X.found;
  return (
    <>
      <At f={f} at={cf(8)}>
        <Put x={x} y={120}>
          <Label size={26} bg={V.red}>2010.4 · 北京银谷大厦</Label>
        </Put>
      </At>
      <At f={f} at={cf(9)}>
        <Put x={x + 60} y={300}>
          <Photo w={320} h={240} caption="创始团队（示意）">
            <People n={14} seed={7} />
          </Photo>
        </Put>
      </At>
    </>
  );
};
```

- **`<At f at until>`** 是唯一的时间控制手段。`at` 用 `cf(n)`（这句开始）或 `cw(n, '词')`（说到这个词时），`until` 可选。
- **`<Put x y>`** 定位在桌面坐标上（绝对坐标，不是相对相机）。
- 一个节点 4–8 个元素，按这句话讲到哪儿逐个落下（`cf(n)`、`cf(n)+12`、`cw(n,'1999')`）。

## 四、`until`：用完即撤

**这是这一期踩到的最贵的坑**：钩子场景（2026 年的市值、雷军、MI）没有写 `until`，一直留在桌面上，播到 4 分钟结尾的「澎程」时，它们还在画面左边挤着。

规则：

- **钩子 / 开场场景的元素全部写 `until`**，收到下一个节点开始前（`<At f={f} at={cf(1)} until={cf(8) - 6}>`）。
- **「同一节点内的元素不用 `until`」这句是错的**（ep58 纠正）：元素确实会随相机移出画面，但那要相机走够远。节点间距只有 1100–1400 世界像素时，上一页挂在 `x + 420` 的印章会一直**半截卡在左边缘**，整页都在。凡是从当前节点往右铺超过 `+ 300` 的元素，都要给 `until`。
- **`until` 的时机要落在镜头移动过程中**。`At` 是硬切（`f >= until` 直接返回 `null`，没有淡出），停在静止画面上删会看见东西突然消失；挑相机正在横移的那十几帧，动作盖得住。反过来说，`at` 是硬切出现，所以「翻页后落位再弹出来」是符合这套视觉语言的，不用改。
- 但**相邻节点的元素如果 y 值接近，会叠在一起**。这一期 MIUI 段的「后来所有争议」便签留到了 798 那一拍，压住了「30 万台」大字 —— 跨段的便签、印章、索引卡一定要给 `until`。
- **每个 `At at={cf(n)}` 都要问一句：这个 `n` 对应的相机停在哪？** 叙事顺序和锚点不是一回事。ep58 泡沫段的便利贴、崩盘段的「3.42 港元」，都写在上一段的组件里、却挂在上一段的 `X` 上，而相机那时已经推到下一个节点 —— 整页被甩出屏幕左边，只剩一条边。这不是「偏移没调好」，是锚点错了，调 `cam.x` 永远修不回来。

排查方法：把关键帧渲出来看，元素重叠在静态帧上非常明显。

## 六、硬规则

1. **动画是帧号的纯函数**。随机只用 `rand(seed)` / `seed` 参数，不能用 `Math.random()`，否则渲染出来每帧都在抖。
2. **不画真实人物肖像**，用 `Portrait` 网点人像代替；**不画第三方 logo**，要画就自己重绘简化版并标「示意」。
3. **`timeline.ts` 不能 import 任何 `.ts` / `.tsx`**，它会被 Node 直接加载用来算时间轴。
4. **示意内容都要标「示意」**（照片、图表、产品外观）。
5. 素材库不反向 import `src/episodes/`。
6. **右上角 `x ≥ 1490 / y ≤ 210` 是年份计数器的地盘**，叙事元素排布时避开，装饰元素用 `hudFade` 自动让开（详情见第八节第 3 条）。

## 七、抽查自检

改完必须先渲关键帧看，不要直接渲整片（8–12 分钟/次）：

```sh
node .workbuddy/skills/weilanx-creator-timeline-video/scripts/frames.mjs <期> 28 1906 3584 7060
```

看四件事：

1. **元素有没有叠**（便签压大字、印章压照片）
2. **字有没有出画**（大字 / 标签被画面边缘切断）
3. **命运线和年份计数器是否同步**（`CapLine` 的 `x1` 要跟相机走）
4. **该撤的有没有撤**（钩子场景的残留）

有问题改完只重渲那一帧，确认了再渲整片。

## 八、ep53 踩的坑（相机与锚点）

这几条都是「代码里看着对、渲出来才发现」的，改一期要一分多钟，按这个清单先自查能省两轮。

**1. 相机的锚点必须和道具的锚点一致。**
C&C08 的机柜一开始挂在 `X.bench` 上，相机却推到 `X.cc08`，两个年份（1991.5 / 1993.6）在桌面上差 1100px，结果整块道具被甩出画外。**道具是哪个年份的事，就挂那个年份的 `X`**；同理，相机也别推到 `X.sanction` 而去拍挂在 `X.peak` 上的一整列内容（ep53 的实体清单段就是这么把整列推到画面左边缘裁掉的）。

**2. 屏幕上下都有安全区，`z` 越大越容易撞。**

底部字幕条从 `subY`（ep53 是 965）开始。世界坐标换屏幕坐标：

```
screenX = (worldX - cam.x) * cam.z + 960
screenY = (worldY - cam.y) * cam.z + 540
```

一列内容从 `y=150` 排到 `y=850`（700px 高）时，**z 只要超过 0.98 就会顶进字幕条**。ep53 钩子原来 `z=1.26`，「1.38 万亿」整个被字幕压掉一半，压到 `z=1.12` + 镜头上抬 60 才留出 20px 间隙。**排完一列先算最下面那个元素的屏幕 y。**

**3. 右上角是年份计数器的地盘，世界里的东西不许漂进去。**

`YearCounter` 是**屏幕固定层**，压在整个世界层上面。实测占位：盒宽 330 + 左右 padding 18 = **366**，右边距 36、上边距 28，盒高约 **150**，阴影再往右下 8。

```
HUD 本体占  x 1518–1884、y 28–178（视觉到 ~190）
禁区（含呼吸）x ≥ 1490、y ≤ 210
```

撞进去的后果不是"看不见"，是**切掉一半**：一排灰色刻度只剩最后两个字露在 HUD 左边，一句注释从右边缘钻出来半句，比什么都没有难看十倍。ep58 的市值刻度「1000 亿」就被切成了「00」，ep56 也有一处年份标签在右侧缝里露半截。

两类东西分开处理：

- **叙事内容**（大字、卡片、便签、印章、照片、人物卡）：**排布时就别放进去**。写完一个节点的元素表，把 `(worldX, worldY)` 代进上面的公式，算一下它在**最远的那个相机位置**（该节点里 `cam.x` 最小、`z` 最大的一帧）下落在屏幕哪儿；`screenY < 210` 的一律下移，或者换成靠左的锚点。一屏之内上半部右侧那一角，留白就行。
- **装饰内容**（市值刻度、网格标签、图例、格线注释）：用 `library/vox/hud.tsx` 的 **`hudFade(wx, wy, w, h, cam)`** —— 它按世界矩形算屏幕位置，接近禁区时返回 1→0 的透明度，`×` 到 `opacity` 上就自动淡出，相机横移时是平滑的、不闪。硬判用 `hudHit`。别自己写阈值，`HUD_SAFE` 就在同一个文件里。参考 ep58 `CapGrid`。

`HUD_BOX` / `HUD_SAFE` / `hudHit` / `hudFade` / `toScreen` 都在 `hud.tsx` 顶部，改尺寸只改 `HUD_BOX` 一处。

**4. 相邻年份的两个标注牌必须手动错开。**
`MiniChart` 的 dips 标注按 `sx(y)` 摆，2002 和 2003 在横轴上只差 25px、纵轴只差 19px，两块牌子完全叠住。给每个标注单独留 `dx/dy` 字段，**横向差 < 200px 就要错开纵向**。

**5. 长的静态图例要挂在「相机的上游」。**
「红线：历年销售收入（对数刻度，示意）」原来挂在 `X.top500 + 120`，一条长句一直拖进 2012 的镜头，被左边缘切掉半句。改挂 `X.top500 - 760`，相机走到下一段之前它自己先出画。**凡是 not-`At` 的常驻文字，都要想一遍相机往右走之后它落在哪。**

**6. `rollYear` 不能和 `xy(camX)` 跟踪混用。**
`tracking ? xy(camX) : rollYear(...)` 这种写法，在 tracking 结束的那一帧，`rollYear` 会**从自己的上一个 stop 重新滚一遍**（ep53 是 1987 闪回 2026 再滚下来，闪 0.87 秒）。要么全程 `rollYear`，把倒带做成一条长 roll（ep53 用 120 帧从 2026 滚到 1987，和相机飞回起点同步）；要么全程跟踪，别混。

**7. 两版之间的过渡留 8 帧以上的重叠。**
`until = cf(N) - 8`、下一个节点 `at = cf(N) - 6`，中间 2 帧是空的。甩镜中段拍到的空桌面不算 bug，但如果镜头已经落了、内容还没起，就是明显的空帧——`until` 和 `at` 要交叉，不要留缝。

## 九、同一期还想做「翻页版」？

ep53 另做过一版完全不用相机的整片（`ep53-huawei-history-gilded`，36 页、265 秒）：**同一套口播、配乐、核查表，只把画面层换成「一页一张账 + 16 帧交叉淡化」**。那套铺法已经独立成 skill **`weilanx-creator-gilded-long-video`**（切页算法、12 种页型、版面网格、组件 API、踩坑全在里面），本文件不再重复。

只留一句提醒：**它和长卷是互斥的两种语法**——长卷让观众跟着镜头走（一屏 3–4 件、靠先后出场），翻页让观众自己扫（一屏 6–8 件、同时在场）。同一期两版都做时，第 1–4 步（查证、写稿、配音、配乐）和核查表可以整份复用，只有第 5–7 步的画面层要重写。
